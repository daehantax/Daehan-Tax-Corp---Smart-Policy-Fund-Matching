> `scripts/research/estimate_cost.py` 산출물. C-1 실측 글자수 기반.

> ⚠ **토큰 수는 추정치다.** 정확한 값은 `count_tokens` 엔드포인트로 재야 하는데
> 이 환경에 자격증명이 없다. 아래는 글자→토큰 비율을 범위로 둔 계산이다.
> 키가 생기면 `--ratio` 로 실측값을 넣어 다시 돌릴 것.

## 4. 비용을 줄이는 수단 (효과 순)

| 수단 | 효과 | 비고 |
|---|---|---|
| **재분석 회피** (`content_hash`) | 일일 비용의 대부분 | 내용이 안 바뀐 공고는 다시 분석하지 않는다. 이게 1순위 |
| **Batch API** | **50%** | 야간 배치라 지연 무관. 최초 백필에 특히 |
| **내용 선별** | **22%** | 자격 단서 없는 문서는 AI에 넣지 않는다 |
| **프롬프트 캐싱** | 시스템 프롬프트 부분 ~90% | 스키마·판정규칙이 전 요청 공통. **Batch 와 병용 가능한지 확인 필요** |
| `effort` 하향 | 가변 | 정확도와 맞바꾼다. 골든셋(A-4)으로 측정한 뒤 결정 |

> **최초 백필은 1회성이다.** 지속 비용은 일일 증분이고, 재분석 회피가 걸리면
> 실제로는 신규 공고 약 45건만 분석한다.

## 5. 확정 사항

- **모델**: `claude-opus-5` — 자격 조건 추출은 오탐이 곧 매칭 사고이므로 정확도 우선.
  더 싼 모델로 내리는 결정은 골든셋(A-4) 정확도를 측정한 뒤 GH가 판단한다.
- **Batch API 사용** — 최초 백필과 일일 증분 모두. 지연 민감도 없음.
- **재분석 회피** — `content_hash` 가 같으면 건너뛴다 (A-8 버전 관리와 같은 해시 사용).
- **내용 선별** — 자격 단서가 있는 문서만 AI에 넣는다 (C-1 결론).
